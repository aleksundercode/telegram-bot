# Telegram: покупки и дела

Node.js 24, Telegraf 4, Redis. В каждом чате свои покупки и дела; в группе списки общие. Выбор текущего раздела сохраняется отдельно для каждого участника.

## Запуск

```sh
cp .env.example .env
# Укажите TOKEN, полученный в @BotFather.
docker compose up -d --build
docker compose logs -f bot
```

Не запускайте одновременно две polling-копии с одним токеном. Для личного бота задайте `ALLOWED_CHAT_IDS` в `.env`, например `123456789,-1001234567890`. Пустое значение разрешает любой чат. ID можно посмотреть через Telegram `getUpdates` при остановленном боте; не публикуйте URL с токеном.

## Использование

| Команда / кнопка | Действие |
| --- | --- |
| `/start`, `/help` | Справка и клавиатура |
| `/products`, 🛒 Покупки | Перейти к покупкам |
| `/tasks`, 📋 Дела | Перейти к делам |
| `/buy молоко` | Добавить покупку |
| `/todo оплатить интернет` | Добавить дело |
| Обычный текст | Добавить в выбранный раздел; по умолчанию — покупки |
| Несколько строк | Отдельная запись на каждую строку, до 20 за раз |
| Нажатие на запись | Закрыть дело / отметить покупку купленной |
| `/done`, ✅ Завершённые | Восстановить или удалить завершённые записи |
| `/reminders` | Показать состояние напоминаний |
| `/reminders on`, `/reminders off` | Включить / выключить напоминания для чата |

Длина записи — до 500 символов. Списки разбиваются на страницы по 6 записей. В группе обычный текст доступен при отключённом Privacy Mode через BotFather; команды `/buy` и `/todo` доступны без этого. Настройку напоминаний в группе меняет только администратор. Для команд можно использовать суффикс `@имя_бота`.

## Напоминания

Включены по умолчанию. Ежедневно в **10:00 Europe/Moscow (МСК)** бот отправляет количество и первые восемь открытых дел, с кнопкой открытия списка. Покупки не вызывают напоминаний. Проверка каждые 30 секунд, часовой пояс хоста не влияет.

Если в 10:00 бот был выключен, после запуска до полуночи МСК он отправит напоминание за текущий день, если остались дела, созданные не позднее 10:00. Если все дела добавлены после 10:00, напоминание придёт следующим утром. За прошедшие дни сообщения не догоняются. Результат отправки хранится в Redis и переживает перезапуск. При аварии между доставкой Telegram и сохранением результата возможен повтор: Telegram не предоставляет идемпотентный ключ для sendMessage. Ошибки доставки повторяются, блокировка бота отключает напоминания до `/reminders on`.

## Обновление старого бота

1. Сделайте резервную копию Redis (RDB после завершения `BGSAVE`). Остановите старого бота.
2. Сохраните прежнее имя Compose-проекта и том `redis`: **не выполняйте `docker compose down -v`**. При смене директории запуска используйте прежний `docker compose -p ИМЯ_ПРОЕКТА …`.
3. Укажите `LEGACY_CHAT_ID` — ID чата, в который перенести старый общий список. Без этого старые записи не видны новому боту, но остаются в базе.
4. Выполните `docker compose up -d --build`, проверьте журнал импорта и `/products`.
5. После успешного переноса можно убрать `LEGACY_CHAT_ID`. Повторный импорт безопасен: каждая запись переносится один раз, в том числе старый ключ `product:null`. Исходные ключи не удаляются. Старый список закрепляется за одним чатом.

Новая схема использует ключи `v2:*`, атомарный счётчик ID и атомарное изменение состояния записей. Redis не публикуется на хост; данные сохраняются в томе, AOF включён. Завершённые записи остаются до ручного удаления. При миграции проверьте восстановление резервной копии: Redis обновляется с 6.2 до 7.4. Для отката используйте резервную копию, а не новый AOF.

## Разработка и проверки

```sh
cd bot
npm install
npm test
# Redis-интеграционные тесты: только отдельная тестовая БД!
TEST_REDIS_URL=redis://localhost:6379/15 npm test
# Локально TOKEN и REDIS_URL задаются в окружении.
npm start
```

Интеграционные тесты очищают выбранную БД через FLUSHDB. Для production она не должна использоваться. Генерация lock-файла требует доступа к npm: после `npm install` сохраните новый `package-lock.json` в Git. Старый lock удалён, поскольку он относится к несовместимым зависимостям v1; Docker поддерживает сборку как с новым lock через `npm ci`, так и первый запуск без него через `npm install`.

Документация: [Telegram Bot API](https://core.telegram.org/bots/api), [Telegraf](https://telegraf.js.org/), [node-redis](https://redis.io/docs/latest/develop/clients/nodejs/), [Redis persistence](https://redis.io/docs/latest/operate/oss_and_stack/management/persistence/).
